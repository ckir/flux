Why Flux?

  • Correctness Before Performance

    Files are never silently corrupted or half-written. Destination locking, streaming BLAKE3 verification, and atomic publication guarantee absolute data integrity.

  • Strict Bounded Resident RAM

    Traditional copiers blow up resident memory when scanning millions of files or deep trees. Flux guarantees an O(1) resident RAM footprint with bounded discovery streams.

  • Topology-Aware & Resumable

    Preserves hardlink topologies accurately, even across filtered subsets. If interrupted, 64 MiB advisory checkpoints continue from proven prefixes without recopying matching data.

How it works

Flux is inspired by FastCopy, but engineered on a modern Rust architecture designed around correctness, bounded resident memory, persistent operation state, deterministic traversal, resumability, and filesystem-native acceleration.

Traditional file copy tools recursively load entire directory hierarchies into RAM, creating unbounded memory consumption and unpredictable behavior when traversing millions of files. Flux replaces this with bounded streams and backpressured worker queues, maintaining a steady, bounded memory envelope regardless of dataset size.

When transferring large files or interrupted workloads, Flux protects your data with cryptographic checkpoints:

in a tree copy, a file of 64 MiB or more continues after the longest leading run of chunks whose digests match on both the source and the destination, and everything else is recopied; a single-file copy of 64 MiB or more continues a half-copied file from its proven prefix (the partial is re-read and hashed against the source); under --durability=normal a checkpoint is advisory and is validated against the data before it is trusted

For an in-depth stage-by-stage architecture breakdown, explore How Flux Architecture Works or read the authoritative specification in the repository: FLUX_FULL_UPDATED_SPEC_V16.md.

The Transfer Pipeline

Every transfer operation flows through a 10-stage bounded pipeline that decouples directory scanning from physical I/O workers:

  1. Source
  2. Deterministic scanner
  3. Selection / filtering
  4. Bounded discovery stream
  5. Topology + planning state
  6. Bounded transfer queue
  7. Parallel workers
  8. Streaming hash / verification
  9. Commit / atomic rename
  10. Report

Workspace Crates

Flux is composed of six modular, decoupled Rust crates in a single cargo workspace:

  • flux-core

    Engine Core

    Deterministic scanner, selection filtering, bounded discovery stream, topology planner, scheduler, transfer queue, parallel workers, and resume engine.

    Crate details | API rustdoc

  • flux-fs

    Filesystem Layer

    Portable filesystem abstractions, destination locking, atomic directory publication, and capability detection.

    Crate details | API rustdoc

  • flux-platform

    OS Fastpaths

    Kernel-level copy acceleration: Linux copy_file_range and splice, macOS clonefile, Windows ReFS block cloning.

    Crate details | API rustdoc

  • flux-hash

    Cryptographic Hash

    High-throughput BLAKE3 streaming verification and chunk-level advisory checkpoint digests.

    Crate details | API rustdoc

  • flux-ui

    Terminal Presentation

    Responsive terminal progress bars, human-readable status, and machine-readable NDJSON streaming output.

    Crate details | API rustdoc

  • flux-cli

    CLI Dispatcher

    Command-line argument parsing and command dispatch; produces the unified flux binary.

    Crate details | API rustdoc

Extract and run

tar -xzf flux-x86_64-unknown-linux-gnu.tar.gz   # Linux and macOS: use the archive you downloaded
Expand-Archive flux-x86_64-pc-windows-msvc.zip . # Windows (PowerShell); or: unzip flux-x86_64-pc-windows-msvc.zip

The binaries are not code-signed, so macOS Gatekeeper or Windows SmartScreen may warn the first time you run one.

Quickstart

Run the extracted binary from its folder (or put it on your PATH).

Linux and macOS

./flux copy ./photos /mnt/backup

Interrupted? Run it again with --resume:

./flux copy --resume ./photos /mnt/backup

Windows

.\flux.exe copy .\photos D:\backup

Interrupted? Run it again with --resume:

.\flux.exe copy --resume .\photos D:\backup

Install Commands

Install Flux via terminal package fetch or build from source using Cargo:

  • curl -fsSL https://github.com/ckir/flux/releases/latest/download/flux-x86_64-unknown-linux-gnu.tar.gz | tar -xz
  • cargo install --git https://github.com/ckir/flux flux-cli

These commands work on Linux, macOS and Windows (via PowerShell or WSL).

Goals

  • High throughput, but correctness before performance
  • Bounded resident RAM regardless of tree size
  • Deterministic discovery and traversal ordering
  • Hardlink topology preservation, including exclusion-aware dependencies
  • Robust resume after interruption, with checkpoint validation
  • Source-mutation detection
  • Atomic publication where the filesystem allows it
  • Clear human and machine-readable (--json) reporting
  • Cross-platform behaviour on Linux, macOS and Windows with explicit capability detection
