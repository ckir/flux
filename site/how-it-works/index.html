How Flux Architecture Works

An engineering deep-dive into bounded memory traversal, advisory checkpoint validation, and kernel-accelerated transfers.

The Core Dilemma: Memory Exhaustion in Traditional Copiers

Standard filesystem copiers (such as default cp -r or recursive rsync) traverse filesystem trees by loading entire directory hierarchies into heap memory before scheduling transfers. On large enterprise datasets—containing millions of files or deeply nested trees—this approach causes resident RAM to explode proportionally with dataset size, leading to thrashing, out-of-memory (OOM) kills, and non-deterministic ordering.

Furthermore, when long-running transfers are interrupted by hardware resets or network disconnects, traditional copiers either recopy entire multi-gigabyte files from scratch or rely on timestamp heuristics that miss corrupted sectors.

The Flux Architectural Solution

Flux is designed from the ground up to solve these fundamental flaws through three core architectural tenets:

1. Bounded Discovery Streams

The scanner runs as an independent generator bounded by backpressure. Directory nodes are discovered, ordered deterministically, filtered, and pushed into a bounded queue. Resident RAM remains strictly capped (typically <64 MiB) whether copying 10 files or 100 million files.

2. Advisory Checkpoint Validation

Large files (64 MiB or greater) are tracked in 64 MiB chunk digests using streaming BLAKE3 hashing. When resuming an interrupted transfer, Flux re-reads the partial file and compares chunk digests against the source. Matching prefixes are preserved; only unverified remainder chunks are recopied.

3. Kernel-Level Zero-Copy Acceleration

Flux detects platform capabilities at runtime and activates direct kernel fastpaths: copy_file_range on modern Linux, clonefile extent cloning on macOS APFS, and ReFS block cloning on Windows, bypassing user-space buffer copies entirely.

4. Hardlink Topology Preservation

Flux discovers inode topologies and replicates hardlink graphs accurately, even when exclusion rules filter out specific branches. Hardlink dependencies are scheduled deterministically so no file is transferred multiple times.

The 10-Stage Transfer Pipeline

  1. Source Scanner: Deterministic lexical directory traversal.
  2. Selection & Filtering: Exclusion patterns, symlink policy evaluation.
  3. Bounded Stream: Backpressured channel with strict memory caps.
  4. Topology Planner: Hardlink graph tracking and inode clustering.
  5. Bounded Transfer Queue: Work-stealing worker queue.
  6. Parallel Workers: Multi-threaded I/O with platform fastpaths.
  7. Streaming Hasher: Incremental BLAKE3 cryptographic verification.
  8. Advisory Checkpointer: 64 MiB chunk validation for resumability.
  9. Atomic Committer: Rename-into-place publication on target filesystems.
  10. Reporter: Structured NDJSON telemetry and terminal progress.
