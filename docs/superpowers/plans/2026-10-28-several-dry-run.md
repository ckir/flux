# `flux copy --dry-run` with several sources (cut 18) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `flux copy --dry-run a b c DEST` (and `--dry-run --restart [--break-lock]`) prints one combined plan with a per-root breakdown, writes nothing and takes no lock.

**Architecture:** `trees()` (`crates/flux-core/src/run/multi.rs:449`) branches to a new `dry_trees` just before `drive`, after the Group 1 steps the real run takes. `dry_start` (`run/mod.rs:1291`) gains a `create_preview` hook that previews the prefix locks, the alias check, the fold-probe and the target check in the real run's order; `copy_roots_at` (`tree.rs:770`) learns to walk against an absent DEST. The CLI drops the `--dry-run` gate arm and prints a dry per-root line.

**Tech Stack:** Rust workspace (`flux-fs`, `flux-core`, `flux-cli`), `FaultFs` fake for engine tests, `cargo nextest`, `just check`.

**Spec:** `docs/superpowers/specs/2026-10-28-several-dry-run-design.md` (panel record in its section 9; read it first, this plan argues from it).

## Global Constraints

- Repo gate: `just check` (fmt-check, clippy `--all-targets -- -D warnings`, typos, licence headers, tests via nextest). Expected pass line: exit 0. Do not invent stricter flags.
- Nextest filters: `test(/(^|::)NAME$/)` (a library unit test's name carries its module path: `run::multi::trees_tests::NAME`); add `--no-fail-fast` whenever the claim is "nothing else went red".
- Commit trailer on every commit: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` (an implementer uses its own model name). Never write a short git sha in prose or commit bodies (typos gate): full 40-hex or none.
- Never run `git checkout`, `switch`, `stash` or `reset`.
- A dry run writes nothing under DEST or its parent, takes no OS lock, creates no lock file or state directory (spec G3).
- No new `unprobed` key and no change to the one-source dry run's output (spec A3, N4). `unprobed` keys stay `noreplace_publish`, `target_lock`, `owner_liveness`, `lock_takeover`, `prior_operation`.
- Every comment and doc line is ASCII-clean where the repo's typos/ASCII gates require it; comments follow the surrounding density (short, why-not-what).
- Windows and macOS legs are verified only by CI after the push; engine tests normalise paths through `calls()` (`multi.rs:1106`).

## Review Focus

1. A DEST on a case-folding filesystem with `Data` and `data` as sources: T14 (residue lock file) and T16 (fresh DEST, probe).
2. Two hardlinked EXISTING targets from an earlier copy must not refuse: T4 hardlink control.
3. A prior several-source run plus a wrong-kind target: the refusal must come before any `would_discard` record: T6, T13.
4. An unreadable prefix lock beside a `.flux-dir.lock` or a wrong-kind target: the real run's order wins: T4 order cases.
