# Cut 11a: `flux copy --dry-run` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `flux copy --dry-run SOURCE DEST` reports every action the real run would take and changes nothing: no lock, no workspace, no claim, no partial, no destination write.

**Architecture:** One engine path with a dry mode (spec D1): the run's read-only pre-flight is reused, the lock and workspace are skipped, the walk runs against a null claim store with `Frame::Live.dir: Option<D>` for directories that do not exist yet, and every per-file decision stops at the point where the first destination write would happen. `stage_file`'s read-only prelude is extracted so the dry stop and the live copy make the same decision. A new non-failure cause `TreeFailureCause::Planned` streams one line per entry; the JSON gains `dry_run` and `unprobed` only when set.

**Tech Stack:** Rust (workspace as is; no new dependency), `cargo nextest`, the `FaultFs` fake, `tempfile` for real-filesystem tests, the `flux` binary through `CARGO_BIN_EXE_flux`.

**Spec:** `docs/superpowers/specs/2026-10-17-cut-11a-dry-run-design.md` (r6, owner-approved, panel GREEN). Section numbers below are the spec's.

**Base:** `origin/main` after PR #107 (merged 2026-10-17 14:38Z). The spec branch `spec/cut-11-dry-run` is older; the controller merges `origin/main` into it before Task 1. Line numbers below were read on that code and are anchors for the implementer's own read, never a substitute for it.

## Global Constraints

- I1: the destination-side methods a dry run may call are exactly `destination_root`, `metadata`, `read_dir`, `read_link`, `mount_root` (`FileSystem`) and `open_dir`, `metadata`, `read_dir`, `read_link`, `identity`, `mount_root`, `canonical_path`, `lock_capability`, `read_file` (`DirHandle`). Nothing else, ever.
- I3: no `open_read` of a source file; every planned copy stats its source and checks `FileType::File`.
- I4: no `try_lock`, `create_lock`, `open_lock`.
- I6: `dry_run` lives on `RunConfig` (D6), never on `CopyOptions`, `state::Options` or the fingerprint; the pinned fingerprint `6814cb38cd3fe6c13a382a988c9c5cbac2ebcf30be0bb4af44596d3019b19f1d` (`crates/flux-core/src/state.rs`) stays.
- I7: DEST's own creation is counted after the walk, never when the walk aborted with `TreeAbort::refused_unchanged()`.
- N2: same-run namespace collisions are not predicted. D7: `--dry-run` with `--resume`, `--restart` or `--break-lock` is usage, exit 2. D8: one stderr line per entry, no quiet flag. D9: no timing measurement in this cut.
- The live path stays byte-for-byte: every existing test is an oracle; a live run's output, JSON (18 keys) and exit codes do not change.
- Gate: `just check` (fmt, clippy, nextest) exits 0. Also, as this project does for every cut: `cargo check -p flux-core -p flux-cli -p flux-platform --target x86_64-pc-windows-gnu` and the same with `clippy` exit 0 (library and binary only: the mingw C toolchain for tests is not installed here; CI runs the Windows and macOS tests).
- Commit trailer: `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. The controller commits; a subagent never runs `git checkout/switch/stash/reset/commit`.

## Review Focus

1. A user previews, then runs for real, and the real run refuses with `RESUMABLE_OPERATION_EXISTS` because a prior operation sits at DEST: the preview must have said so. Pinned by Task 4's prior-note tests and Task 6's CLI prior-note test.
2. A script reads `--dry-run --json` and treats `files_copied` as work done: `"dry_run": true` must be present on every dry JSON, including a pre-engine stop. Pinned by Task 6's JSON tests.
3. DEST exists and is a regular file: a tree source is the CLI's usage error (exit 2) in both modes, and a DEST below a regular file is the engine's pre-flight refusal (exit 1) in both; the preview must not pretend to plan. Pinned by Task 6's exit-code test. (corrected after execution, ruling P8)
4. The source changes while the preview runs (a directory becomes unreadable): the preview reports the walk failure and exits 1, and still writes nothing. Pinned by Task 3's `dry_a_source_that_fails_to_list_is_the_live_walk_failure`.
5. The preview says "would copy" for a file whose destination is a hardlink alias of the source, which the real run refuses: the gate must run at the dry stop. Pinned by Task 3's `dry_a_hardlink_alias_of_the_source_is_refused_as_live_does`.
