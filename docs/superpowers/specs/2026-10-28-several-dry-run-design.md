# `flux copy --dry-run` with several sources (cut 18)

Status: draft for owner approval. Not built. Branch `feat/several-dry-run` off main `d59cd83e6790b8ec18e0da7774094f964b96581f`.

## 1. Intent

`flux copy a b c DEST` refuses `--dry-run` today (`crates/flux-cli/src/main.rs:650`, `several_flag_gate`; the engine entry `crates/flux-core/src/run/multi.rs:459` asserts `!cfg.dry_run`). `--restart` and `--break-lock` work with several sources since cut 17. This cut lets an operator preview a several-source copy, and a several-source `--restart`, the way cut 11a and 11b let them preview a one-source copy: read everything a real run would read, say what it would do and which refusal it would meet, change nothing.

Owner decision (2026-10-28): the output is ONE combined plan with a per-root breakdown, mirroring the real run's report (the `roots` array and the summed counters). Owner decisions on the three forks (agy and the author agreed on each): slicing S2, engine shape A, prefix-lock disposition P3 (section 3).

## 2. Goals, non-goals, anti-goals

Goals
- G1. `flux copy --dry-run a b c DEST` prints the plan of a fresh several-source copy and exits as the one-source dry run does: 0 when the plan completes, the real run's exit code for a refusal it can predict.
- G2. `flux copy --dry-run --restart a b c DEST` and `--dry-run --restart --break-lock a b c DEST` preview what the real invocation would do at a DEST holding prior state: the priors superseded, the half-copied files and state directories discarded, a destination-lock takeover (cut 11b's vocabulary, over format-5 priors).
- G3. A dry run writes nothing under DEST (or its parent), takes no OS lock, creates no lock file and no state directory. This is the one-source dry run's property (spec of cut 11a, `docs/superpowers/specs/2026-10-17-cut-11a-dry-run-design.md`).
- G4. Every refusal the real run raises from information a READ can decide is predicted with the same error code: a same-name collision, a source that is not a regular file or folder, DEST inside a source, an object of the wrong kind at `DEST/<name>`, an unreadable, foreign or untrusted prefix lock.
- G5. The per-root counters sum to the totals, as in the real report.

Non-goals
- N1. `--resume` with several sources, with or without `--dry-run` (the next cut). `--dry-run --resume a b c DEST` stays exit 2 naming `--resume`.
- N2. Predicting that a prefix lock is HELD. A held and a dead (L6 residue) prefix lock carry the same bytes (`workspace_path` = `none`), and only trying the OS lock tells them apart (`dry_run` reads files; `dry_lock` states "It never opens the lock", `crates/flux-core/src/run/dry_prior.rs:51`). A readable trusted prefix lock is reported as the dual outcome the destination lock already is: `owner_liveness` in `unprobed`. The same blindness covers a prefix lock file that is empty or torn because its holder is inside the first write: the dry run reads it as `TARGET_LOCK_UNCERTAIN` where the real run says `TARGET_LOCK_BUSY` (cut 11b's "empty-lock blind spot", TODO.md); both refuse, so G4's "same error code" holds except for that case.
- N3. Predicting a same-name collision from case folding (or normalisation) where the fold-probe of section 4.2 step 2 (vi) cannot decide. The real run finds such a collision by creating the second lock file, which opens the first one's file and meets its own record (`PrefixRefusal::Collision`, `prefix.rs:136-152`); `create_lock` is its probe and a read has none, so the dry run reads instead: an existing lock file that two names resolve to (step 2 (iv)), or the folding of the directory itself learned from an existing entry (step 2 (vi), owner decision 2026-10-28: build the probe in this cut). Still blind: (a) a directory with nothing to probe with (no entry holding an ASCII letter in DEST or, when DEST is absent or has none, in its parent); (b) folding that is not ASCII case (Unicode case, normalisation: NFC against NFD); (c) filesystems whose identities are `Weak` or `Unavailable` (FAT32, exFAT), where the probe cannot compare an entry with its variant. (`check_targets` compares each target only with its own source, and `plan_roots` compares prefix keys byte for byte, so neither catches an alias between two roots.)
- N4. Any change to the one-source dry run's output.

Anti-goals
- A1. A dry run that reports a plan the real run would not follow. Where the dry run cannot know (N2, N3) it says so (the `unprobed` list), it never guesses a favourable outcome.
- A2. Streaming `would_discard` records for a run that then refuses: the live order is destination lock, scan, prefix locks and target check (`place.create`), then supersede (`session.rs`); the preview keeps that order (section 4.2).
- A3. A new `unprobed` key or a changed JSON key set for the one-source dry run.

## 3. Approaches considered (the owner chose the first of each)

Slicing: S2 (this design): the fresh plan plus `--restart` and `--restart --break-lock` previews, because the real invocation after an aborted several-source run is `--restart` and cut 11b's `dry_start` and `dry_restart` already work over format-5 priors through `Place::scan` (`MultiPlace::scan` delegates to `TreePlace::scan`). S1 (fresh plan only) keeps the change smaller but builds the dry driver once and re-opens it for the prior previews, and needs its own gate for `--dry-run --restart`.

Engine shape: A (this design): `trees()` branches to a dedicated `dry_trees` just before `drive`, after the same Group 1 steps the real run takes (names, sources, `locate_dest`, preflight and containment, capability, control plane), as `tree_with` branches to `dry_tree` (`run/mod.rs:377`). B (generalise `dry_tree` over `Place`) would put multi-root walk types on the `Place` trait. C (the CLI calls the one-source dry run per source) cannot work: it scans `DEST/<name>` for priors instead of `DEST`, applies the one-file policy to file roots, walks in argument order with separate hardlink slots, and counts an absent DEST once per source.

Prefix locks: P3 (this design): `dry_lock` per prefix. P2 (do not look) misses refusals that certainly stop the real run. A naive "any readable record is BUSY" refuses where the real run recovers L6 residue.

## 4. Design

### 4.1 CLI (`crates/flux-cli/src/main.rs`, `report.rs`)

- `several_flag_gate` refuses only `--resume` (message unchanged: "error: --resume with several sources is not supported yet; run again with --restart to supersede an aborted several-source run"); `--dry-run` alone and with `--restart` / `--break-lock` pass. `--dry-run --resume` prints the `--resume` message (the first arm, as today).
- `copy_several`: the two `Report::pre_engine` arms (`main.rs:696`, `:703`) set `r.dry_run = args.dry_run`, as the one-source arms do (`:470-471`, `:478-479`).
- The dry output of a several-source run, in the order `tree_output` prints it (`main.rs:600-630`) plus the new pieces: the streamed `would_*` records (`<name>/...` paths), `tree_warning_lines`, `run_lines(run)` (the `RunWarning` notes, which is where `DryRunPrefixLocks` lands, after the destination lock's own note and before the prior lines), the dry prior lines, the `unprobed` lines, the per-root lines, the dry summary line, `dry_extra_lines`. `Report::several_run` + `tree_output` already take `Run`; a dry run sets `rep.dry_run`, `rep.unprobed` from `unprobed_keys` and zeroes `average_bytes_per_second`, as `copy` does for one source (`main.rs:506-511`).
- Per-root line in a dry run (author's call R2, amended by panel round 1): `root <name>: would copy <n>, <m> would fail` (the real run's `root <name>: <n> copied, <m> failed` would read as if something had been copied). `<m>` is the SAME counter the real line prints, `files_failed` (copy failures only, `report.rs` `Report::tree`); the summary's `errors` counts every failure class, so a root that failed on a walk or create error shows `would fail 0` and status `failed`. `root_lines` gains a dry flag (`root_lines(roots, dry)`) and `not started: ...` is unchanged.
- `--json`: the dry report carries `"dry_run": true` and the same `roots` array and keys as a real several-source report; a root's `status` is `completed` when its plan reached the end, `failed` when it counted an error, `not_started` after an abort. No new key.
- `--help` of `copy` and the doc comment at `main.rs:39`: "--resume needs one source" only.

### 4.2 Engine (`crates/flux-core/src/run/multi.rs`, `run/mod.rs`, `tree.rs`)

`trees()` returns `dry_trees(...)` when `cfg.dry_run`, right where `drive` is called today, with the `MultiPlace` already built (its `tree.dest` may be `None`). `dry_trees` is `dry_tree` for several roots:

1. `dry_start` (run/mod.rs:1291) gains one parameter, `create_preview: &mut dyn FnMut(&mut DryRun, &mut Vec<RunWarning>) -> Result<(), RunError>`. It is called (a) in the `cfg.restart` branch BEFORE `restart_preview`, and (b) in the "no resumable prior" branch; not in the refusal branch (the real run refuses at the scan before `create`). A refusal returns `DryStart::Stop(stop, dry)`; the closure sets `dry.owner_liveness = true` itself, TOGETHER with pushing the `DryRunPrefixLocks` note (the key is announced by the note, `report.rs:528`): both when the loop completes with at least one trusted record, so both survive a later `check_targets` refusal and neither exists when the loop itself refuses. `dry_tree` and `dry_file` pass a closure that does nothing. This is the ordering of anti-goal A2.
2. The multi `create_preview`: if DEST is absent, only the fold-probe (vi) can run, on DEST's parent (there are no lock files or targets to read). Otherwise:
   (i) ONE `read_dir` of DEST is read, names only, and shared by the whole preview. If it FAILS, the `.broken.*` scan notes nothing (best-effort, as `dry_lock`'s own scan, `dry_prior.rs:108-109`); nothing else depends on the listing. `dry_lock` lists its directory once per call for `.broken.*` leftovers (`dry_prior.rs:108-120`); the prefix calls use a variant that does NOT list, and ONE pass over the shared listing, keyed by the roots' lock names, owns every `DryRunBrokenLeftover` note of the prefix locks (O(entries + roots)). The destination lock's own call is unchanged.
   (ii) For each root name, in the order `PrefixLocks::acquire` takes the locks (prefix order, stopping at the first refusal): first `LockSite::directory(dest, name)` is built and a construction error becomes `PrefixRefusal::Lock { name, error }` (after `plan_roots`' `prefix_lock_fits`, `roots.rs:113`, it cannot fail; the mapping is the defensive twin of `take`, `prefix.rs:107-113`); then the alias check against the lock names before it (iv); then, if `metadata` of `DEST/<name>.flux-lock` says NotFound (the lookup, not the listing, so a folded spelling counts as present, as `create_lock` would find it) and `DEST/.flux-dir.lock` is present, the refusal `TARGET_LOCK_BUSY` with the real text ("a directory lock (.flux-dir.lock) is present beside the target's lock", `lock/acquire.rs:50-60`) naming that lock path: the real `acquire` reaches the directory-lock check only for a name whose lock file it just created (`acquire.rs:42-45` returns early for an existing file), so a root whose lock file exists is judged by its own record first; then `dry_lock(&site, false, capability, now, &mut local)` (break-lock is false: `--break-lock` covers the destination lock only, cut 17 P1). `Refused` and `Error` become `PrefixRefusal::Lock { name, error }` through `MultiPlace::prefix_error` (the same text as the real refusal, the lock file named once); `Recorded` records the name for the note; `Takeover` cannot occur with `break_lock` false.
   (iii) `local` is a scratch warnings vector: `dry_lock` pushes a `RunWarning::DryRunLockRecord` itself for a trusted record (`dry_prior.rs:93-104`), which names no lock, so the loop DROPS those, collects the names that produced one, and after the loop pushes one `RunWarning::DryRunPrefixLocks { names: Vec<String> }` (lossy strings, rendered joined by ", ") and the leftover notes. If the loop refuses, the scratch is discarded (the real `MultiPlace::create` returns its error with no warnings of earlier roots). If the loop succeeds and `check_targets` then refuses, the `DryRunPrefixLocks` note and the leftover notes are KEPT, as the real run has already pushed its `BrokenLeftover` warnings (`multi.rs:275-278`) before `check_targets` (`:280`).
   (iv) The alias rule, on LOCK files only, needs NO listing: two root names `a` and `b` alias when `metadata` of `DEST/<a>.flux-lock` and `DEST/<b>.flux-lock` both succeed with equal `Strong` identities. Flux creates every lock file with its own `create_lock`, so two names with one identity are the filesystem folding one onto the other, and the real run's collision is exactly that (the second `create_lock` meets the first one's file and its own record, `PrefixRefusal::Collision`, `prefix.rs:136-152`; two hardlinked lock files would collide the same way). Targets are NOT compared with each other: two hardlinked existing targets (a previous copy under the default `Hardlinks::Auto`) must not refuse, and on Windows or a normalising filesystem a target spelling can resolve without being a lock alias. `metadata` is called once per name (a map from identity to the first name), so the check costs O(roots) calls. An alias refuses with `DestinationNamespaceCollision` through `prefix_error(PrefixRefusal::Collision { name, other })`, the real run's code and text; `Weak` and `Unavailable` identities never decide. The shared listing of (i) is used only for the `.broken.*` notes.
   (v) Only after the whole loop `check_targets` runs (made to take the DEST handle as an `Option`, `None` = skip), as in `MultiPlace::create`, where `PrefixLocks::acquire` (`multi.rs:268`) precedes `check_targets` (`:280`): an unreadable prefix lock on root 2 beside a wrong-kind target on root 1 reports the lock, as the real run does.
   (vi) The fold-probe, lazy and read-only. It runs only when two root names are equal after ASCII lower-casing while differing in bytes (e.g. `Data` and `data`); otherwise it is skipped and costs nothing. It decides whether the directory the lock files live in folds ASCII case: `folds_ascii_case(dir, entries) -> Option<bool>`. Walk `entries` (the shared listing of DEST; when DEST is absent, or its listing has no usable entry, the listing of DEST's parent `holder`, read once and only now, on the assumption that a directory made in a folding parent folds too) for the first entry whose name is valid UTF-8 and holds an ASCII letter; its variant swaps the case of that name's first ASCII letter. If the variant is itself an entry of the listing, two names differing only by case coexist, so the directory is case-SENSITIVE: `Some(false)`. Otherwise `metadata` of the entry and of the variant: both `Strong` and equal is `Some(true)` (the lookup found the same object under another case); the variant NotFound is `Some(false)`; anything else (an error, a `Weak` or `Unavailable` identity) tries the next entry and, with none left, is `None` (undecided, no refusal: blind case (a) or (c) of N3). It never creates, renames or removes anything. When it returns `Some(true)`, the alias check of step (iv) for a name also reports an alias with any EARLIER name that is ASCII-case-equal to it, at the same position of the loop (before the directory-lock check and `dry_lock` of that name, as the real `take` meets the first lock's file before it classifies anything), with `PrefixRefusal::Collision { name, other }` as in (iv). A false refusal is worse than a missed prediction (anti-goal A1), which is why every doubtful path is `None`.
3. The walk: one `Shared` base with the dry settings of `dry_tree` (`dry_run: true`, unguarded, no heartbeat, `NullClaimStore`, the deferred hardlink slot in the temp directory shared by ALL roots, as the real run shares one slot), `for_root` per root. `copy_roots_at` (tree.rs:770) takes `dest: Option<&F::Dir>`, `None` only in a dry run with DEST absent, and a new `anchor: FileIdentity` (the identity of DEST's holder when DEST is absent, as `dry_tree` takes it from `place.holder.identity()`, `run/mod.rs:1463-1467`; nothing in `Shared` or `RootInput` carries it). For a folder root in a dry run the root directory is `dest.open_dir(name)` with THREE outcomes: `Ok(dir)` is `Some(dir)` with `RootIdentity::Existing`; `NotFound` (or DEST absent) is `None` with `RootIdentity::Planned(identity of DEST, or `anchor` when DEST is absent)`; any other error aborts the root with `CopyStep::Create`, as the live `create_dir` failure does (`tree.rs:860`), never a silent fresh plan, `directories_created += 1`, and a `<name>` `would_create` record is streamed (R1: a root folder is a directory the real run creates, as a subdirectory is; DEST itself is counted, not streamed, as in one source). The walk is `copy_tree_frames` (what `dry_tree` calls), not `copy_tree_at`. For a file root with DEST absent, `root_state` takes `None` and `RootIdentity::Planned`, `copy_one` takes `parent: None`, and no batch is drained. A DEST that was absent adds one to `directories_created` after the walk unless the walk refused with nothing changed (`dry_tree`'s I7).
4. `dry_top_level_flux` (tree.rs:1252) treats a top-level child named `.flux` as DEST's workspace directory. In a several-source folder root the walk's top level is `DEST/<name>`, never DEST, and a real run copies `<name>/.flux` as ordinary content. The function returns `false` when `cx.key_prefix` is `Some` (every folder root of a several-source run sets it). Pinned by a paired dry/real test (section 5).
5. The outcome: `MultiRun` with `run.dry = Some(dry)` and `roots` built from the same per-root diff `copy_roots_at` computes. `dry.unprobed_noreplace = true`, as in one source.

Unchanged: the lock-free property. `dry_trees` never calls `drive`, `PrefixLocks::acquire`, `create_dest`, `supersede`, `finish`.

### 4.3 What the output says where a read cannot decide

`unprobed` keeps the one-source tree dry run's vocabulary and order (`noreplace_publish`, `target_lock`, `owner_liveness`, `lock_takeover`, `prior_operation`; `report.rs:532`). A readable trusted prefix lock sets `owner_liveness`. `RunWarning::DryRunLockRecord` carries no lock path (`report.rs:778`), and k prefix locks of one crashed run share one operation id, so k identical notes would not say which lock they describe: the prefix locks print ONE new note instead, `RunWarning::DryRunPrefixLocks { names }`: "note: the prefix lock records of <names> are readable; their owners' liveness was not probed; a real run refuses with TARGET_LOCK_BUSY for each whose OS lock is held" (author's call R6). The destination lock's existing note and variant are unchanged. N3 (absent case-folded names) has no key and no line: it is recorded in `docs/accepted-boundaries.md` and the `--help` text of `--dry-run` (author's call R3: a new key would change the contract, anti-goal A3).

## 5. Tests (the oracle for the plan)

Engine (`FaultFs`, `crates/flux-core/src/run/multi.rs` tests):
- T1. Two folder roots and a file root into a fresh DEST: the plan, per-root counts, totals equal the sum, `directories_created` counts DEST once plus each folder root, root `would_create` records present.
- T2. Pairing: for the same fixture, the dry plan's counters equal the real run's (copied, skipped, overwritten, directories, errors), and the dry call log contains no write, create, rename, remove or lock operation (the allow-list style of cut 11a).
- T3. DEST present with existing targets: overwrite/skip/up-to-date per root as the one-source dry run.
- T4. Refusal parity, dry vs real: wrong-kind target (file root over a directory, folder root over a file), source inside DEST's target, an unreadable prefix lock (`TARGET_LOCK_UNCERTAIN`), an orphan prefix lock (`ARTIFACT_OWNERSHIP_UNCERTAIN`), a foreign one; each has the same code and the same detail text. Order cases: an unreadable prefix lock AND a wrong-kind target on the same root report `TARGET_LOCK_UNCERTAIN`; and across roots, a wrong-kind target on root 1 beside an unreadable prefix lock on root 2 reports root 2's lock (a `check_targets` run per root inside the loop would report root 1's target). A directory lock `DEST/.flux-dir.lock` present refuses `TARGET_LOCK_BUSY` at the first root whose lock file is absent, naming that root's lock path, and a root with an unreadable existing lock file BEFORE it reports its own `TARGET_LOCK_UNCERTAIN` instead (the per-name order of `acquire.rs:43-50`). Hardlink control: two existing targets of one inode (a previous copy with the default `Hardlinks::Auto`) do NOT refuse; the same fixture is a dry re-run after T9's cross-root hardlink copy (exit 0, both files skipped).
- T5. A readable trusted prefix lock: the plan completes, `owner_liveness` is set and the `DryRunPrefixLocks` note names exactly that root; a stale L6 residue (dead prefix lock) does not refuse, as the real run recovers it. Warning assertions: the trusted-record case with TWO roots holding readable trusted locks yields exactly one `DryRunPrefixLocks` naming both and NO `DryRunLockRecord` from a prefix lock; the mixed case that refuses leaves the run's warnings free of root 1's notes. Mixed case also asserts `owner_liveness` is NOT set. Combined case: a readable trusted prefix lock (and a `.broken.*` leftover) on root 1 plus a wrong-kind target on root 2: the run refuses with the target's code AND the prefix note, the leftover note and `owner_liveness` are all present (the real run pushed its leftovers before `check_targets`). Negative control: DEST present with NO prefix lock file leaves `owner_liveness` unset and prints no prefix note. Mixed case: root 1's prefix lock readable and trusted, root 2's unreadable: the run refuses with root 2's `TARGET_LOCK_UNCERTAIN` (the loop does not stop at the first `Recorded`).
- T6. `--restart` over a crashed several-source prior (cut 17's `crashed_ab`): `DryPrior::Restart` lists the prior, its partials and state directory, the `would_discard` records stream, nothing changes on the fake. Ordering: with a wrong-kind target at DEST, the dry `--restart` refuses with the real code and has streamed NO `would_discard` record (A2).
- T7. `--restart --break-lock` with an empty destination lock: `lock_takeover` is set and the plan continues; with an unreadable prefix lock too, the prefix refusal is returned (cut 17's T4b, dry).
- T8 (the fixture has NO `.flux` entry under `DEST/<name>`, because `dry_top_level_flux` returns false when `open_dir` finds one, `tree.rs:1270-1275`). A root containing a regular file `.flux` directly under it: the dry plan agrees with the real run (copied, no `SAFETY_REJECTED`); and a `.flux` directory.
- T9. Hardlink groups spanning two roots: one shared slot, the dry counts match the real run's `files_hardlinked`. The fixture sets `cfg.dry_temp_root` to a directory that exists on the fake (`trees_tests::cfg()` leaves it `None`, `multi.rs:1047`, which sends the index to the host temp directory).
- T10. `--exclude` and `--no-recursive` per root: per-root `excluded` counts sum to the total.
- T11. DEST absent: no prefix-lock reads, no `check_targets`, every root planned new; run with the default and with the strictest `--safety` option (the planned root identity is the holder's, not `Unavailable`). T11b: DEST present with a folder root target that `open_dir` cannot open for a reason other than not-found: the root aborts with the create-step error, as the real run does.
- T13. A plain dry run (no `--restart`) over a crashed several-source prior refuses with `RESUMABLE_OPERATION_EXISTS` naming `--restart`, as the real run does, and streams nothing; the crashed-prior fixture ALSO plants a wrong-kind target, so a `create_preview` run before the `RESUMABLE_OPERATION_EXISTS` refusal would report the target instead and fail the test; a dry `--restart` with DEST absent previews an empty supersede and the fresh plan.
- T12. An abort-class failure in root 2 (the builder picks a trigger the fake can inject, for example a failing `open_dir` of root 2's existing target; a source read error is NOT abort-class: `walk_into` counts it as a walk failure and continues): root 1 `completed`, root 2 `failed`, later roots `not_started`. T12b: a counted non-abort failure (a source read error in root 2): root 2 `failed`, root 3 `completed`, the totals and `errors` include it.
- T14. Alias between two roots, on LOCK files: sources `Data` and `data` with an existing residue `DEST/Data.flux-lock` on `FaultFs` with `set_case_insensitive` (`fault_fs.rs:94` is the field, the setter `set_case_insensitive` is at `:1343`) refuse `DESTINATION_NAMESPACE_COLLISION`, the real run's code and text. `FakeDirHandle::read_file` (`fault_fs.rs:2538`) builds `child_path` without `norm`, so a folded spelling reads as absent: the cut makes it apply `norm` as `metadata` does (a test-support change in the FILES list of the plan). Fixtures that each turn a different mutant red: the mirror (residue `data.flux-lock`, sources `Data`, `data`); three roots with a third BETWEEN them in the bytewise prefix order of `plan_roots` (`roots.rs:132`): `Data`, `Mid`, `data` (`other` would sort after `data`); the residue present and the DEST listing made to FAIL (the alias is still reported: the rule needs no listing); two hardlinked EXISTING lock-free targets (no refusal); and equal `Unavailable` (and, separately, equal `Weak`) identities on the two lock files, set with the fake's existing `set_identity` (`fault_fs.rs:1283`), which must NOT alias: `FileIdentity` derives `PartialEq` (`flux-fs/src/fs.rs:93`), so a plain `==` would refuse; the comparison matches only when both are `Strong`. It guards the check on every CI leg and is never skipped; a real-volume variant (like `an_alias_is_refused_on_a_case_insensitive_destination`, `crates/flux-cli/tests/several_sources.rs`) is an addition, not the guard. A fresh DEST with no lock file is T16's, not T14's.
- T16. The fold-probe, on `FaultFs` with `set_case_insensitive` (`fault_fs.rs:1343`) and the real run as the oracle for each row: sources `Data` and `data`, (1) DEST absent, the parent holds an entry with a letter, folding on: the dry run refuses `DESTINATION_NAMESPACE_COLLISION`, the real run's code and text; (2) the same with folding off: the plan proceeds; (3) DEST present with entries: the probe uses DEST's own listing (the parent is not listed: the call log has no `read_dir` of the parent); (4) DEST present but holding only digit-named entries, folding on in the parent: the parent probe decides; (5) nothing with an ASCII letter anywhere: undecided, the plan proceeds (blind case (a)); (6) two entries `Ab` and `aB` both listed: case-sensitive, no refusal; (7) no two root names equal after lower-casing: no probe, no extra `read_dir` or `metadata` in the call log; (8) a non-UTF-8 entry name is skipped; (9) equal `Unavailable` identities on the entry and its variant: undecided, no refusal; (10) with a residue lock file and the probe both applicable the refusal is the same single `Collision`; (11) the probe's position: an earlier root with an unreadable lock file reports `TARGET_LOCK_UNCERTAIN` before the collision, as the real `acquire` order does. A mutant that probes with the byte-equal name instead of the swapped one, one that treats `NotFound` as `Some(true)`, and one that probes always (not lazily) each turn a different row red.
- T15. DEST's creation count: DEST absent and the plan completes: `directories_created` counts DEST once plus each absent folder root; DEST absent and the walk refuses with nothing changed (`TreeAbort::refused_unchanged`, whichever trigger the fake can inject): DEST is not counted. The first half is pinned always.
