# `flux copy --resume` with several sources (cut 19)

Status: reviewed (2026-10-28): panel round 1 folded 4 findings, round 2 GREEN. Branch `feat/several-resume` off main `c7a4798f73f0e309fdca3fad04275f0cb8139fb6`.

## 1. Intent

`flux copy a b c DEST` is one operation: one manifest (format 5, one `Root` per source), one `state.db` of claims keyed per root, one WAL, one destination lock, and one prefix lock file `DEST/<name>.flux-lock` per root. `--restart` (cut 17) and `--dry-run` (cut 18) work with several sources; `--resume` is the last flag the several-source flag gate refuses (`crates/flux-cli/src/main.rs:650`, `several_flag_gate`; the engine asserts `!cfg.resume` at `crates/flux-core/src/run/multi.rs:693`; `MultiPlace::adopt` refuses at `multi.rs:598`; the dry preview refuses at `multi.rs:938`). This cut lets an operator continue a killed several-source run exactly as `--resume` continues a one-source tree run, and preview that with `--dry-run --resume`.

Owner decisions (2026-10-28): slicing F3(a): the real resume and the dry preview land in ONE cut (agy recommended it; the author preferred two cuts and the owner chose one). Settled by agy and the author without dissent: F1 exact source-list match; F2 re-take the prior's prefix locks at adoption; F4 the single keyed claim store suffices.

## 2. Goals, non-goals, anti-goals

Goals
- G1. `flux copy --resume a b c DEST` over a killed several-source run continues it as the same operation: the files the prior completed are skipped and verified as the one-source resume does (cuts 9a, 9b, 9f, 15), the half-copied ones continue, the rest are copied; the prior's workspace is retired at the end; every prefix lock ends released.
- G2. `--resume` with no resumable prior starts a new operation (`ResumeNote::StartedNew`), as the one-source resume does.
- G3. The source list must equal the prior's: same count, and, root by root in prefix order, the same name, kind, and source (identity where `Strong`, else the lexical path). Any difference is `INCOMPATIBLE_STATE` naming the first differing root and `--restart`. Every other row of `resume::validate`'s table applies unchanged.
- G4. `flux copy --dry-run --resume a b c DEST` previews the real invocation: the compatibility verdict, the claim count and recovery notes, the files it would skip, continue and copy, with the real run's refusal codes for what a read can decide. It writes nothing under DEST, takes no lock, and its output keys match the one-source dry resume's.
- G5. Every refusal of the one-source resume has its several-source analogue with the same code (`INCOMPATIBLE_STATE`, `STATE_CORRUPT`, `COMMIT_STATE_UNCERTAIN`, the prefix-lock refusals).

Non-goals
- N1. A changed source list (an added, removed or reordered source), by any merge: it is refused and `--restart` is the way out.
- N2. Resuming a one-source tree prior with several sources, or the converse: refused by the count row of `validate` (exists today).
- N3. Everything N2, N3, N4 of the cut 18 spec say about the dry run's blind spots (a prefix lock's held state; fold-probe limits; two lock names hard-linked to one file) stays as accepted.
- N4. Any change to the one-source resume or dry resume output.

Anti-goals
- A1. A resumed run that leaves a prefix lock file behind, or releases one a live run holds.
- A2. A resume test that passes because everything was copied again: tests assert skipped counts and the identity and mtime of a completed file.

## 4. Design

### 4.1 Flag gate and docs
`several_flag_gate` is deleted (its only arm was `--resume`); `copy_several` stops calling it. The `Copy` doc comment (`main.rs:39`) says all four flags work with one or several sources; the `--resume` help line is unchanged apart from that. The test `resume_exits_2_naming_the_flag` (`crates/flux-cli/tests/several_sources.rs:151`) is replaced (section 5). ROADMAP.md (Phase 2 and Phase 8 rows), TODO.md (L1 and the several-source open items), `docs/accepted-boundaries.md` (L1 text), and the cut 17 and cut 18 specs (a dated note under their N1) are updated.

### 4.2 Compatibility: `resume::validate`
`validate` (`run/resume.rs:81`) checks `roots.len()` against the stored count, then compares only `roots.first()` and `then.destination_prefix != now.destination_prefix`. It is generalised to every root, in order: for root `i`, `kind` equal (a manifest `kind` is `Some` for format 5; a one-root manifest has `None` and is compared only when both are `Some`), `destination_prefix` equal, source identity equal where both are `Strong`, else `source_root` equal, else the existing `source_mismatch` message. **(call)** the existing one-root messages do not change byte for byte (the one-source tests pin them); with more than one stored root every message of this row is prefixed `root <name>: ` (the stored root's prefix name). The new `kind` text, which the one-source path never produces, is pinned here: `the operation copies a <folder|file>, this run's source is a <folder|file>; run again with --restart to supersede it`. The destination-prefix text is the existing one. Weak-identity roots matched by path (`ResumeMappingByPath`, `resume.rs:80`, `151`): `by_path` becomes a `Vec<PathBuf>` and the warning is pushed once per such root, in order (panel round 1, AB-1: the scalar kept only the last root's path). Everything after the roots row is untouched.

### 4.3 Adoption: `MultiPlace::adopt` (`multi.rs:598`)
The real order is: `session.rs` step 4 picks the prior, `validate` (4.2) runs, THEN `place.adopt` runs (`session.rs:181-189`). So a compatibility refusal comes before any prefix-lock refusal. `adopt` today refuses. It becomes, in this order:
1. Open the prefix locks as `create` does: `lock_directory`, `PrefixLocks::acquire(dir, capability, &names, &prefix_id)`, store them in `self.prefix`, push the `.broken` leftovers as `BrokenLeftover` warnings; a refusal goes through `prefix_error` as today. `acquire` has released what it took.
2. `check_targets()` (wrong-kind and same-as-source refusals); on error release the locks (`warn_release`) and return it. A resumed DEST holds the partial copies, which pass: a directory at a folder root, a file at a file root.
3. `self.tree.adopt(prior, durability, warnings)` (the one-source adoption: open or recreate the store, commit recovery). On error release the locks. The error changed nothing (the one-source adoption's own rule); the prefix lock files are removed by the release, so a refused resume leaves DEST as it found it except for `.broken` residue a recovery moved aside.
Order rationale: the locks are the only step of the three that can be undone by a release, so they go first; the store is last because its `CREATED` repair removes and creates a file.

### 4.4 Release: no change to `MultiPlace::remove`
A resumed run's `finish` calls `place.remove(&locked.state.operation_id)` (`run/mod.rs:1189`) with the ADOPTED id, which is not this run's id, so `MultiPlace::remove` (`multi.rs:545`) takes its "retire a prior's workspace" branch and releases nothing. That is correct: `drive` calls `settle` before `finish` on every path (`run/mod.rs:701`; the opening-failure path at `460`), and the several-source `settle` is `release_prefix_locks` (`multi.rs:876`), which drains `self.prefix`. The locks are therefore released, in the spec's order (locks before the workspace is retired), before `remove` runs. **Correction (panel round 1, MG-1; the author's earlier draft added an `adopted` id arm to `remove` and said agy had missed a defect: the claim was wrong, agy's statement that the locks are released at the end was right).** The `debug_assert!(!cfg.resume, ..)` at `multi.rs:693` is deleted and its comment, which concerns a supersede, is rewritten. The consequence for tests: an end-to-end resume cannot show that `remove` is right (`settle` hides it), so T2 is the end-to-end assertion that no `*.flux-lock` file remains, and T4 shows the adoption refusals release the locks (the only release `settle` does not cover is the one inside `adopt`, which runs before the walk).

### 4.5 The real run
`trees()` (`multi.rs:683`) no longer asserts `!cfg.resume`. `session.rs` step 4 already picks `scan.resumable.remove(0)` under `cfg.resume` and calls `validate(&prior, &place.roots(), ...)` then `place.adopt`; `MultiPlace::roots()` already returns one `Root` per source. The report shows the one-source resume notes (`resume_lines`, `report.rs:830`) and the per-root lines; `files_resumed` is a total. The `root <name>: <n> copied, <m> failed` line (`report.rs`, `root_lines`) and the `--json` `roots` entries (`name`, `status`, `files_copied`, `files_failed`) show THIS invocation's counts, so a root finished before the kill prints `0 copied, 0 failed`; the files skipped as already complete are in the totals and the `resumed <k> already-complete files` summary only (panel round 2, measured at `report.rs`). **(call)** no per-root resumed counter is added in this cut; a note in the help and README says so. Exit codes are those of the one-source resume.

### 4.6 The dry preview
`dry_trees` (`multi.rs:918`) replaces its refusing `resume_preview` with the one-source shape (`run/mod.rs:1427`): `dry_adopt` on a private copy of the store, parked for the walk; the walk then runs with `claims` = the copy, `resume: true`, `dry_prior: Some(id)`, `dry_partials` set. `dry_adopt` and `adopt_on_copy` (`run/dry_prior.rs:267`, `287`) take a `&TreePlace` and call `place.roots()`, which for the tree inside a `MultiPlace` is the ONE-root answer; they gain a `roots: &[Root]` parameter (the one-source caller passes `place.roots()`).

The dry run must meet the refusals in the real order: compatibility (`validate`), then the prefix locks, then `check_targets`, then the store adoption (4.3). Today `dry_start` calls the `create_preview` hook only on the fresh and `--restart` arms; its doc says "never a resume" (`run/mod.rs:1297`, the arms at `1347-1356`), so the cut 18 lock preview would be skipped for a resume. **(call, found by the author's panel round)** the `ResumePreview` closure type gains a `&mut DryRun` parameter; its three callers are `dry_tree` (`run/mod.rs:1427`), `dry_file` (`run/mod.rs:1579`) and `dry_trees`, and the first two ignore it (panel round 1, CA-1). In `dry_trees` the `temp_root` and the parked `adopted` store move above `dry_start`, as in `dry_tree`. The several-source closure runs, in order: `validate` (via the first step of `adopt_on_copy`, or called first and left to repeat: it is pure), `place.dry_create_preview(dry, warnings)` (the locks and `check_targets_in`, which set the `DryRunPrefixLocks` note and `owner_liveness`), then the private store copy. The `dry_start` doc comment is rewritten. The aggregated note and `owner_liveness` are as in cut 18 (N2 there).

## 5. Tests (the oracles the plan names; each must fail under its mutant)
Engine (`multi.rs` test modules, fake filesystem): (T1) a killed several-source run (the fixture kills after root 1 completed and during root 2) resumed to completion: files completed before the kill are not rewritten (identity and mtime), the counts say `resumed`, the tree equals an uninterrupted run's, the prefix lock files are gone (A1, A2). (T2) the end-to-end resume of T1 leaves no `*.flux-lock` file under DEST, and `MultiPlace::remove(other id)` still releases nothing (existing test `remove_of_a_prior_keeps_this_runs_prefix_locks`); `settle` hides `remove` from a full run, so no test claims to cover it (panel round 1, MG-1). (T3) `validate` rows: a different count, a swapped pair, a renamed root, a kind change, a changed source identity, each refused with the first differing root named; the one-root messages unchanged. (T4) adoption refusals release the locks: a foreign prefix lock, a wrong-kind target, a torn store, `COMMIT_STATE_UNCERTAIN` (mutants: skip the release). (T5) `--resume` with no prior starts new (`StartedNew`), with a dead prefix lock residue present (the kill-between-locks state). (T6) a `CREATED` prior without a store is recreated. (T7) a one-source tree prior with several sources, and a several-source prior with one source, are refused `INCOMPATIBLE_STATE`.
Dry: (T8) `dry_agrees`-style: the dry resume plan of T1's state agrees with the real resume's counts and changes nothing under DEST; (T9) each refusal of T3 and T4 is predicted with the real code; (T10) `--dry-run --resume` with no prior plans fresh; (T11) the temporary store copy is removed.
CLI (`several_sources.rs`, the Linux-only kill harness cut 17 copied): (T12) kill mid-run, `--resume`, exit 0, the destination equals the sources, completed files untouched; (T13) the same with `--dry-run`, nothing changes; (T14) `--resume` with a changed list exits with `INCOMPATIBLE_STATE`'s exit code, the text names `--restart`; (T15) `--help` mentions several sources for all four flags. ## 6. Accepted boundaries and residuals
- B1. A prefix lock file of a dead run whose record is unreadable refuses the resume as `TARGET_LOCK_UNCERTAIN` (the text of cut 17 and 18), and the operator removes it or uses `--restart`. This is the existing prefix-lock rule, not a resume decision.
- B2. A source list that changed since the kill is refused (N1).
- B3. The cut 18 dry-run blind spots (N2 to N4 of that spec) apply to the dry resume.
- B4. A recovered prefix lock's move-aside file `<name>.flux-lock.broken.<this run's id>` is deleted right after the replacement lock is taken (`lock/recover.rs:89-91`); only a failed deletion leaves it, reported as `BrokenLeftover` and found by `flux cleanup` (`cleanup/discover.rs:322`). Successive kills therefore do NOT accumulate asides (corrected during Task 2: the draft claimed they did, from an unmeasured peer statement). The id is still this run's own, so a leftover of an earlier attempt can never collide with a later `rename_no_replace` of the same name.
